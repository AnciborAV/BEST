ОПОРА: первый запуск на Render

Render собирает приложение из GitHub и запускает на внешнем сервере. Компьютер автора может быть выключен. Project объединяет сервисы; Web Service запускает Java и принимает запросы посетителей.

Подготовленные файлы
Dockerfile уже собирает JAR на Java 25 и запускает его непривилегированным пользователем. application-render.properties включает внешний интерфейс и временную H2 в памяти. RenderProfileTest проверяет запуск этого профиля без PostgreSQL. render.yaml описывает тот же сервис для альтернативного запуска через Blueprint.

Ограничение текущего этапа
Сейчас публикуются информационные страницы без аккаунтов и личных записей. Тексты и изображения входят в приложение из GitHub. H2 хранит техническую схему Liquibase и очищается при остановке процесса. Перед добавлением любых пользовательских данных нужна отдельная постоянная PostgreSQL и соответствующий профиль. Файловая H2 на бесплатном сервере тоже не обеспечивает сохранность. Базу и настройки Book_Store не используем.

1. Подготовка
Примите PR страницы «Найти направление» и PR подготовки Render в master репозитория AnciborAV/BEST. Новый репозиторий не нужен. Название BEST не мешает назвать проект OPORA.

2. Новый проект
Вы уже зарегистрированы в Render. Войдите в тот же аккаунт. На экране Projects нажмите Create new project (или New > Project). Название: OPORA. Если предлагается имя окружения, укажите Production. Это название группы, а не выбор платного тарифа. Создайте проект. Book_Store оставьте на месте.

3. Новый сервис
В проекте OPORA создайте Web Service. Другой путь: New > Web Service, затем выберите проект OPORA в форме. В разделе Git Provider подключите GitHub и выберите AnciborAV/BEST. Если репозитория нет, разрешите Render доступ к BEST в настройках GitHub-приложения. Static Site нам не подходит: страницы формирует Java/Spring Boot.

4. Параметры
Name: opora-web (если занято, выберите свободное имя).
Project: OPORA.
Environment: Production, если создали такое окружение.
Region: Frankfurt, если доступен.
Branch: master.
Root Directory: пусто, Dockerfile и pom.xml находятся в корне.
Language / Runtime: Docker.
Dockerfile Path: ./Dockerfile.
Docker Command: пусто, используется ENTRYPOINT из Dockerfile.
Instance Type: Free для первого знакомства.
Health Check Path в Advanced: /.
Auto-Deploy: после успешных проверок CI, если этот вариант доступен; иначе после коммита в master.
Build Command и Start Command вручную не нужны в Docker: команды уже описаны в Dockerfile.

5. Переменные окружения
SPRING_PROFILES_ACTIVE = render
SERVER_ADDRESS = 0.0.0.0
PORT предоставляет Render, обычно 10000. Приложение читает его автоматически. Не подставляйте локальный порт 8081. DATABASE_URL и OPORA_DB_* для этого режима не нужны. Не подключайте группы переменных и базу Book_Store. Секретов для текущего публичного сайта нет.

6. Запуск
Нажмите Create Web Service. Откройте Deploys / Logs. Дождитесь успешной сборки Docker, сообщения Started OporaApplication и статуса Live. Первый запуск может занять несколько минут. Адрес с окончанием onrender.com появится в карточке сервиса. Откройте именно выданный Render HTTPS-адрес.

7. Проверка
На компьютере и iPhone проверьте фон, изображения, меню, диалог «Смысл символа» и его закрытие. Откройте /stability, /hardship и /direction, проверьте переходы с главной, кнопки возврата, читаемость и отсутствие горизонтальной прокрутки. /direction появится после принятия соответствующего PR.

8. Обновления
При включённом Auto-Deploy принятые PR в master запускают обновление сайта. Создание PR само по себе не меняет сайт до слияния. При необходимости используйте Manual Deploy > Deploy latest commit. Проверяйте результат в Deploys и Logs.

Бесплатный режим
Free подходит для знакомства и демонстрации, не для гарантированной постоянной работы. После 15 минут без входящих запросов сервис засыпает; пробуждение занимает около минуты. На workspace выделяется 750 бесплатных часов в календарный месяц, общих для работающих Free Web Services. Если Book_Store тоже бесплатный, он расходует тот же лимит. Два постоянно работающих сервиса могут превысить его. Проверяйте Usage, лимиты трафика и сборки. Внешняя Free Postgres здесь не создаётся: она имеет отдельные ограничения и истекает через 30 дней. Для постоянной работы позже выберите подходящий платный сервис, а для пользовательских данных - постоянную базу.

Если возникла ошибка
Подключение к localhost:5432: проверьте SPRING_PROFILES_ACTIVE=render и выполните deploy после сохранения переменных.
No open ports: проверьте SERVER_ADDRESS=0.0.0.0 и PORT.
Out of memory: сохраните журнал ошибки; бесплатный экземпляр ограничен по памяти.
Нет новой страницы: проверьте слияние PR, ветку master и commit в Deploys.
Долго открывается после простоя: возможно, Free-сервис пробуждается.

Альтернатива: Blueprint
Вместо ручного создания можно выбрать New > Blueprint, репозиторий BEST, ветку master и render.yaml. Проверьте один бесплатный Web Service без внешней базы и запустите Blueprint. При необходимости назначьте сервис проекту OPORA. Выбирайте один способ создания, чтобы не запустить два одинаковых сервиса. При ручном создании render.yaml автоматически не управляет настройками панели.
